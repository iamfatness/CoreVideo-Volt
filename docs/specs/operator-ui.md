# Operator UI

Static page at `/` and `/operator` (`control/volt/session/operator/`: `index.html`, `operator.css`, `operator.js`). No build, no framework, no CDN. Served by `serve.py` with a same-origin-only Content-Security-Policy. The shell is open without a token so it can ask for one; every data route stays gated.

Run it against a fake room, no core needed: `cd control && python -m tests.operator_harness held --port 8791`, then open `/operator`.

## Data

- `GET /api/state?show=<id>` (new, read-only, token-gated). One poll every 2 s (6 s when the tab is hidden). Returns `shows`, `show`, `rundown` (the `/rundown` shape `{hold, items}`, unchanged), `taking` (the id of the item with status `taking`, or `null`), `cues` (each with `failure: {status, detail}` or `null`, the last dispatch failure kept until the cue fires) and `media` per item, `assets` (cleared, legal hold, `blockedBy`, file, checksum), `spans` with `versions` and `label` (the editorial spans, clips and shots, plus any span a rundown item uses or that already has a published version, whatever its kind; transcript words that nothing uses are not in it, since owner ruling on `shot-spans.md` question 9; words are found through `library.search` and the Library), and `room` (the room's recording lifecycle, or why it is unreachable). No show given, or an unknown one, means the newest. `deriveShow` treats a taking item as the current row: transport is not "Nothing on air", Next is not a later ready row, TAKE and GO wait.
- Each `media[itemId]` that has a span also carries `frames` (span length) and `rate` (the hi-res essence frame rate, e.g. `25` or `30000/1001`), both `null` when the asset has no usable rate or the length cannot be counted. The page totals durations from them for front time and drift.
- The page parses the rundown in one function, `parseRundown`, so a change of shape is one edit.
- Actions are the A2 POST endpoints. The page shows the state the server returns and, on refusal, the stable `code` and `reason`. Nothing is shown optimistically. A poll that began before an action finished is discarded.
- A failed cue stays `armed` on the server (taking again resumes there), so the page overlays "Failed" from the last take response until the next take succeeds.

**Scheduling.** `POST /api/items/{id}/schedule` with `{at}` (an ISO time with a UTC offset, normalised to UTC, or `null`) sets or clears when the clock takes an item (operator role, audited). Only a `ready` item can be scheduled; an item that is `on air`, `taking`, `aired`, `skipped` or `killed` is refused with 409 `not_schedulable`, and a naive or unreadable time with 422 `bad_input`. Setting again resets an earlier outcome. `/rundown` items carry `scheduledAt`, `scheduleState` and `scheduleNote`. On the Show row a state chip names the schedule (Scheduled, Claimed, Fired, Failed, Missed, Held, Blocked, or an unknown outcome by its own word) with the time in the viewer's local clock; the build panel's "Take at" control (Producer and Editor layouts) sets or clears it, and the Operator layout shows it read-only.

**Slot length and back time.** A show can carry a planned length (`show.slot_seconds`, 1 to 86399; `POST /api/shows/{id}/slot` with `{seconds}` or `null`; `slotSeconds` in `/rundown`). With one set, the rundown summary reads `Total 12:40 of 15:00` and `Over 00:30` (red, alert icon) or `Under 02:20` (neutral, ready icon), and each ready row shows a **back time**: the time of day by which it must start for the show to end on the slot, which is the slot end less the lengths of that item and every counted item after it. The slot end is the first item's start (actual once it has aired, else its scheduled time) plus the slot; with neither, or with an item of unknown length at or after the row, the back time is `--:--`. Aired items count by their actual length, so the total follows what really happened. Killed and skipped items take no time. The slot is set in the build panel (Producer and Editor layouts, `mm:ss` or `h:mm:ss`; a bare number is refused as ambiguous) and shown read-only in the Operator layout, where the build forms are hidden.

### Media and the token

`<img>` and `<video>` cannot send an `Authorization` header. What the page does:

- Thumbnails: always `fetch()` (header attached when there is a token) into a `blob:` URL, three at a time, cached by span and frame range, revoked when the asset changes or a trim replaces the frame. One path with or without a token, and a trim fetches the new frame instead of a browser-cached one (the thumb route sets `max-age=3600` and takes no query).
- Proxy, no token (loopback): native `<video src="/api/assets/{id}/proxy">`, streamed and seeked by byte range. Nothing changes for loopback use.
- Proxy, token set: fetched with the header into memory first, on an explicit "Load proxy" press (it is a whole-file download), with a progress figure, refused above 512 MB before any body is read (the length comes from the response header), and played from a `blob:` URL. A growing proxy (asset still recording) is a snapshot until "Reload proxy".

Why this and not the alternatives: it changes nothing on the server's auth surface, puts no token in a URL (URLs reach logs, history and referrers), and needs no service worker (which needs a secure context, and a LAN address over http is not one). The cost is real: with a token the operator waits for the whole proxy, and a large proxy cannot be played. If that bites, the next step is a short-lived signed URL for the proxy route; it is not built. The CSP gained `img-src blob:` and `media-src 'self' blob:` and nothing else.

## Keys (Library screen)

Handled only when the Library is the open screen, and never when a field has focus. Space is not TAKE here, and none of the Show keys (T, H, S, X, arrows) do anything here.

| --- | --- |

| `L` | Play forward. Press again for 2x, 4x, 8x. |

The Find tab adds `/` (focus the search field from any Library tab, never inside a field), Up and Down between results, Enter to open, and Esc in a non-empty field to clear it and search again. Details has no keys of its own.

## Scripts screen

On narrow screens the preview sits below the script. The preview marks directions and private notes, and a live count gives words and estimated read time.

## Collaboration screens

Built for the identity plan, in the existing design language and only existing colour tokens (both theme sets; `test_operator_ui.ThemeContrast` measures the pairs they use). State is always icon plus word plus colour, never red for anything but a live path.

- **Sign in.** The Token dialog offers "Sign in with Google" and "Sign in with Microsoft" when the server has `VOLT_OIDC_CONFIG` (unvalidated against a real provider), above the token field, which always works. A cookie session replaces the token in the page; the account button names the person and role. Admins reach Activity and Access from the screen rail.
- **Activity** (admin). The event log lists what happened, the actor, target, and local date and time, newest first. Details expand in place and the exact UTC timestamp is available on the time element. Filter by actor, event, target type, or an inclusive local date range. Suggestions come from loaded events, and exact values can be typed for older events. The applied filters and result count stay visible above the log. On phones, a Filters disclosure leaves more room for the log. Load older events keeps expanded details and moves keyboard focus to the first new row. Download CSV uses the applied filters and includes up to 500 events.

- **Access** (admin). Choose a show to see whether it is Open or Restricted. Assignments lists direct and group permissions with Change and Remove actions. People shows each account's effective View, Edit, Run, or No access, with the contributing assignments and role rules. Add access grants a permission to a person or group. The first grant explains that it restricts the show, and the last removal explains that it opens the show again.
- **Presence.** Avatars and a line under the toolbar say who is on the show and where; a person in two tabs is one name.
- **Edit lease.** Opening a script for editing takes a 45 s lease the page renews every 15 s. Held by someone else, the editor is read-only with a banner naming them and, for an operator with edit access, a Take over button; a lost lease says so in words and keeps the unsaved text.
- **Comments.** A thread panel on the Show screen and a Comments tab in Scripts, mention completion, a Resolve and a delete, and an open-thread chip on rundown rows. Text only; a comment is never rendered as markup.
- **Notifications.** A bell with an unread count and a dialog for mentions, replies and a taken-over lease.
