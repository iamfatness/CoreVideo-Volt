# Roadmap

The end state is the wing. The order is what keeps it from becoming a battleship.

## V1 — the show can find itself

File and live ingest. Checksum. Technical metadata. Proxy with matching timecode, including a partial proxy on a growing file. Search. Span markers. ASR. A bin inside the CoreVideo session. One Premiere panel. No clock. No MOS.

Exit: an editor will live here for one show.

## V2 — the rundown

Stories and items. Script on the item. Cues stored but not yet firing the room, except a manual "take this span to program" through CoreVideo. Multi-destination publish: house file, one OTT package, one social cut. Loudness and captions via an engine, not code we write.

Exit: a crew can run the show list and publish without a newsroom system.

## V3 — the clock and the room

Software playout of the rundown. Secondary events. Cue dispatcher fires CoreVideo inputs, PTZ presets, graphics, and audio snapshots. As-run writes back to the item. On-air tally is law: red means the director is on the air path.

Exit: a wrong cue is a defect, not a roadmap item.

## V4 — the edges

MOS Profile 1 and 2 export. Hardware playout adapter. Archive tier with a restore SLA. Second NLE only after the first relink path is boring.

## Explicitly later

IMF. Deal memos. Face gallery. Network origination. A second switcher.

## Team shape for V1

One media-pipeline engineer, one control-plane engineer, one session UI engineer, part of the existing CoreVideo room work. AI stays a worker.
